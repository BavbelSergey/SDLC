# Использовать WPF в качестве библиотеки построения интерфейса

## Контекст и постановка задачи

WeatherDesk — десктопное приложение для Windows 10/11 на C# (.NET 8) (CON-1, CON-2). SRS оставляет выбор библиотеки интерфейса открытым (OQ-1, вариант по умолчанию — WPF). Интерфейс должен быть адаптивным, с тремя режимами раскладки и минимальным окном 400×600 px (REQ-INT-002, REQ-INT-003), корректно работать при масштабе Windows 100–200% (REQ-PORT-001) и поставляться ZIP-архивом без установщика (REQ-INST-001).

Какую библиотеку построения интерфейса использовать?

## Драйверы решения

* Соответствие обязательному ограничению CON-2: десктопное приложение для Windows 10/11
* Адаптивная раскладка и масштабирование (REQ-INT-002, REQ-INT-003, REQ-PORT-001)
* Тестируемость и шаблон MVVM (REQ-MAINT-001, REQ-MAINT-002)
* Простая поставка без установщика (REQ-INST-001)
* Знакомство разработчика с технологией и малый срок разработки
* Допустимые лицензии (REQ-COMP-002)

## Рассмотренные варианты

* WPF
* Avalonia UI
* WinUI 3
* Windows Forms

## Итог решения

Выбранный вариант: «WPF», потому что он полностью покрывает требования версии 0.1 (только Windows, адаптивная раскладка, масштабирование) при наименьших затратах на освоение, а поставка в виде self-contained ZIP не требует дополнительных компонентов.

### Последствия

* Хорошо, потому что `VisualStateManager`, гибкие панели и устройство-независимые единицы позволяют реализовать три режима раскладки и масштаб 100–200% без сторонних библиотек
* Хорошо, потому что MVVM в WPF стандартен, и ViewModel тестируется без окна
* Плохо, потому что приложение работает только на Windows; поддержка Linux и macOS потребует переписать слой Presentation (слои Application и Infrastructure переиспользуются)
* Плохо, потому что в WPF нет встроенной поддержки векторных изображений, поэтому иконки поставляются в PNG размером 192×192

### Подтверждение

* Инспекция файла проекта: `TargetFramework` равен `net8.0-windows`, включён `UseWPF`
* Ручная проверка на Windows 10 и Windows 11 при масштабе 100%, 150% и 200% (REQ-PORT-001)
* Проверка границ режимов раскладки 900 и 600 px (REQ-INT-002)

## Плюсы и минусы вариантов

### WPF

Зрелая библиотека для Windows с поддержкой MVVM, привязок данных и состояний представления.

* Хорошо, потому что полностью соответствует CON-2 и OQ-1 (вариант по умолчанию)
* Хорошо, потому что адаптивная раскладка и масштабирование решаются штатными средствами
* Хорошо, потому что self-contained публикация даёт ZIP, запускаемый без установки
* Нейтрально, потому что кроссплатформенность не требуется в версии 0.1 (REQ-PORT-001)
* Плохо, потому что привязан к Windows

### Avalonia UI

Кроссплатформенная библиотека, похожая на WPF.

* Хорошо, потому что работает также на Linux и macOS
* Нейтрально, потому что кроссплатформенность не входит в требования версии 0.1
* Плохо, потому что добавляет внешнюю зависимость и требует дополнительного времени на освоение
* Плохо, потому что при выбранной платформе Windows даёт выигрыш, который проекту не нужен

### WinUI 3

Современная библиотека интерфейса для Windows из Windows App SDK.

* Хорошо, потому что современный внешний вид и стандартные элементы Windows 11
* Плохо, потому что поставка без установщика требует дополнительной настройки Windows App SDK, что усложняет REQ-INST-001
* Плохо, потому что поддержка Windows 10 и настройка проекта сложнее, чем у WPF

### Windows Forms

Классическая библиотека для Windows.

* Хорошо, потому что очень простая и привычная
* Плохо, потому что ограниченные средства адаптивной раскладки и масштабирования, а значит, больше ручного кода для REQ-INT-002 и REQ-PORT-001
* Плохо, потому что слабая поддержка привязки данных и MVVM

## Дополнительная информация

Решение закрывает открытый вопрос OQ-1 и подлежит подтверждению Заказчиком вместе с SRS v0.2. Пересмотреть решение нужно, если появится требование поддержки Linux или macOS. Затронутые требования SRS: CON-2, REQ-INT-001 … REQ-INT-003, REQ-PORT-001, REQ-INST-001, REQ-MAINT-001. Представления SDD: 002-composition, 018-ui-adaptive-layout.
