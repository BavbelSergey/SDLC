# Брать код погоды и иконку у основного источника с резервом по приоритету

## Контекст и постановка задачи

Числовые показатели (температура, влажность, давление, ветер) трёх источников усредняются. Код погоды, по которому выбираются иконка и описание (REQ-FUNC-013, REQ-INT-004), — категориальная величина: среднее арифметическое кодов 3 и 61 не имеет смысла. Кроме того, Open-Meteo и ECMWF отдают коды ВМО, а Met Norway отдаёт текстовые обозначения вида `lightrain_day`, которые нужно сопоставлять с 10 иконками.

Как определять код погоды, иконку и описание, если источников три?

## Драйверы решения

* Детерминированный и объяснимый результат (одни и те же входные данные дают одну и ту же иконку)
* Совместимость с таблицей WMO-кодов и 10 иконок из SRS (приложение C)
* Простота реализации и тестирования, срок разработки
* Работа при недоступности основного источника (REQ-REL-005)

## Рассмотренные варианты

* Основной источник с резервом по приоритету
* Голосование большинством
* Выбор самого тяжёлого явления

## Итог решения

Выбранный вариант: «Основной источник с резервом по приоритету», потому что он даёт предсказуемый результат при минимальной сложности. Порядок приоритета: Open-Meteo, ECMWF, Met Norway. Значение берётся у первого по приоритету источника, у которого оно есть; текстовое обозначение Met Norway переводится в ближайший WMO-код только при необходимости.

### Последствия

* Хорошо, потому что иконка и описание всегда согласованы с одним источником и таблицей приложения C SRS
* Хорошо, потому что сопоставление Met Norway потребуется только как резерв и тестируется отдельно
* Плохо, потому что иконка может не отражать мнение большинства источников, если основной источник расходится с остальными
* Плохо, потому что при отсутствии кода у основного источника для данной точки значение берётся у следующего, и иконка может «прыгнуть» между обновлениями
* Для Met Norway нужна таблица сопоставления `symbol_code` и WMO-кодов (SDD, представление 012)

### Подтверждение

* Модульные тесты `WeatherCodeMapper`: все 28 кодов таблицы, код 0 при `is_day=0` даёт «ясно ночью», неизвестный код даёт «пасмурно» и «Нет данных» (REQ-FUNC-013)
* Тесты агрегатора: приоритет основного источника, резерв при его отсутствии, одна иконка при расхождении источников
* Тесты сопоставления `symbol_code` Met Norway

## Плюсы и минусы вариантов

### Основной источник с резервом по приоритету

* Хорошо, потому что результат детерминирован
* Хорошо, потому что реализуется простым правилом «первое доступное значение»
* Хорошо, потому что соответствует таблице кодов SRS без изменений
* Нейтрально, потому что приоритет источников задаётся в одном месте
* Плохо, потому что мнение основного источника перевешивает остальные

### Голосование большинством

Выбирается код, совпавший у большинства источников.

* Хорошо, потому что учитывает все источники
* Плохо, потому что коды у источников редко совпадают точно, а группировка по категориям (дождь, снег) требует дополнительных правил
* Плохо, потому что при трёх разных значениях решение всё равно нужно принимать по приоритету
* Плохо, потому что для Met Norway всегда нужно полное сопоставление обозначений с кодами

### Выбор самого тяжёлого явления

Выбирается наиболее «неприятная» погода (гроза важнее дождя, дождь важнее облачности).

* Хорошо, потому что осторожный подход для пользователя
* Плохо, потому что требует ранжирования всех 28 кодов и вводит пользователя в заблуждение, если один источник завышает явление
* Плохо, потому что результат может расходиться с усреднёнными температурой и осадками, которые показаны рядом

## Дополнительная информация

Это решение упрощает реализацию третьего источника: полное сопоставление обозначений Met Norway с иконками нужно только для резервного случая. Если пользователи будут жаловаться на «прыгающие» иконки, решение нужно пересмотреть в пользу голосования с приоритетом при равенстве. Связанные решения: ADR-0002. Затронутые требования SRS: REQ-FUNC-013, REQ-INT-004, REQ-REL-005 (см. приложение B SDD). Представления SDD: 011-algorithm-aggregation, 012-algorithm-units-and-codes.
