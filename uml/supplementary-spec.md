# Дополнительные спецификации WeatherDesk

Документ содержит требования и ограничения, которые не выражаются отдельными прецедентами: качество, ограничения проектирования, интерфейсы, лицензирование. Источники: [SRS](srs.md), [SDD](sdd/sdd.md), [ADR](adr/). Идентификаторы прецедентов приведены в [модели вариантов использования](uml/use-cases.md), термины определены в [глоссарии](glossary.md).

## 1. Функциональность (общая)

| ID | Требование | Источник | Прецеденты |
|----|------------|----------|------------|
| SUP-001 | Ошибки записываются в журнал `%AppData%/WeatherDesk/logs/app.log`: не более 3 файлов по 1 МБ; в журнал не попадают персональные данные | REQ-OBS-001, SYS-NFR-008 | UC-02, UC-03, UC-12 |
| SUP-002 | Сбой одного или двух источников не приводит к ошибке всей загрузки: данные усредняются по ответившим источникам, показывается «Источников: N из 3» | SRS 1.2, SYS-FUNC-005, ADR-0002 | UC-03, UC-12 |
| SUP-003 | Приложение не завершается аварийно при отсутствии сети, тайм-ауте, HTTP-ошибке и некорректном JSON; пользователю показывается сообщение без технических подробностей | REQ-FUNC-017, REQ-INT-005, SYS-FUNC-012 | UC-02, UC-03, UC-04, UC-05, UC-12 |
| SUP-004 | Все внешние запросы выполняются только по HTTPS; персональные данные и секреты не передаются и не хранятся | REQ-SEC-001, REQ-SEC-003, SYS-NFR-004 | все |
| SUP-005 | Введённый запрос города ограничен 100 символами и кодируется при подстановке в адрес запроса; управляющие символы не интерпретируются | REQ-SEC-002, SYS-FUNC-002 | UC-01 |

## 2. Удобство использования

| ID | Требование | Источник | Прецеденты |
|----|------------|----------|------------|
| SUP-006 | Все данные прогноза доступны с одного главного окна без переходов на другие экраны | REQ-INT-001 | UC-06, UC-07, UC-08 |
| SUP-007 | Сообщения об ошибках понятны, а кнопка «Повторить» показывается там, где повторный запрос имеет смысл | REQ-INT-005 | UC-12 |
| SUP-008 | Все элементы управления доступны с клавиатуры (Tab, Enter, стрелки, Esc, F5); при запуске фокус в строке поиска (версия 1.1) | REQ-INT-006, SYS-NFR-013 | UC-01, UC-04 |
| SUP-009 | Давление по умолчанию показывается в мм рт. ст. с заметной подписью «приведено к уровню моря» | REQ-FUNC-012, ADR-0003 | UC-06, UC-10 |
| SUP-010 | Светлая и тёмная темы переключаются без перезапуска; выбор запоминается | SYS-FUNC-018 | UC-11 |
| SUP-011 | Раскладка переключается между режимами Wide, Medium и Compact на границах 900 и 600 px; горизонтальной прокрутки у окна нет, кроме списка часов; минимальный размер окна 400×600 px | REQ-INT-002, REQ-INT-003, SYS-FUNC-014 | UC-06, UC-07, UC-08 |

## 3. Надёжность

| ID | Требование | Источник | Прецеденты |
|----|------------|----------|------------|
| SUP-012 | Повреждённый `settings.json` или `cache.json` переименовывается в `.bad`, приложение запускается со значениями по умолчанию | REQ-REL-001, ADR-0004 | UC-02, UC-10, UC-11 |
| SUP-013 | Отсутствующие или `null`-значения в ответе показываются как «—» и не мешают показу остальных данных | REQ-REL-002, SYS-NFR-006 | UC-06, UC-07, UC-08 |
| SUP-014 | Ответ устаревшего запроса отбрасывается, если пользователь уже выбрал другой город | REQ-REL-004, SYS-FUNC-003 | UC-02 |
| SUP-015 | Запись JSON-файлов выполняется через временный файл с атомарной заменой; доступ к файлу сериализован | ADR-0004, SDD 014 | UC-02, UC-10, UC-11 |
| SUP-016 | Если обновление не удалось, а на экране уже есть снимок, он остаётся с пометкой времени «Обновлено в …» и сообщением о сбое | SDD 013, переписка 12.11.2026 | UC-04, UC-05, UC-12 |

## 4. Производительность

| ID | Требование | Источник | Прецеденты |
|----|------------|----------|------------|
| SUP-017 | Прогноз показывается не позднее чем за 3 секунды для 95% запросов при нормальных условиях сети | REQ-PERF-001, SYS-NFR-002 | UC-02, UC-04 |
| SUP-018 | Реакция интерфейса на действия пользователя не более 200 мс; сетевые вызовы асинхронны и не блокируют поток интерфейса | REQ-PERF-002, SYS-NFR-003 | все |
| SUP-019 | Источники опрашиваются параллельно; тайм-аут на один источник 10 секунд | REQ-PERF-002, ADR-0002 | UC-03 |
| SUP-020 | Не более 60 запросов в час на один хост; поиск подсказок — через 400 мс после последнего символа; ручное обновление — не чаще одного раза в 10 секунд | REQ-REL-003, REQ-FUNC-001, REQ-FUNC-014, SYS-NFR-007 | UC-01, UC-03, UC-04, UC-05 |

## 5. Сопровождаемость

| ID | Требование | Источник | Прецеденты |
|----|------------|----------|------------|

| SUP-022 | Источник данных заменяется или добавляется регистрацией новой реализации `IWeatherProvider` без изменения ViewModel и окна | REQ-MAINT-003, SYS-NFR-005, ADR-0002 | UC-03 |

## 6. Ограничения проектирования

| ID | Требование | Источник |
|----|------------|----------|
| SUP-025 | Платформа: 64-разрядные Windows 10 (22H2) и Windows 11, C# на .NET 8, интерфейс на WPF | CON-1, CON-2, REQ-PORT-001, ADR-0001 |
| SUP-026 | Приложение — один процесс без собственного сервера и базы данных; данные хранятся в файлах JSON | CON-3, CON-5, ADR-0004 |
| SUP-027 | Ключи API не используются; для запросов к Met Norway обязателен заголовок `User-Agent` с названием приложения и контактом разработчика | CON-4, CON-8, ADR-0002 |
